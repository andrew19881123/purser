# Inference Audit Log (AI Act Art. 12)

The inference audit log records every inference request in a tamper-resistant, append-only table. It is designed to satisfy **EU AI Act Article 12** (record-keeping for high-risk AI systems) while respecting **GDPR Article 5** data-minimisation principles: prompt content is never stored.

---

## What gets logged

Each inference request produces one `InferenceEvent` row:

| Field | Type | Description |
|---|---|---|
| `request_id` | `TEXT` UNIQUE | UUID v4 generated by the gateway. Primary deduplication key. |
| `api_key_hash` | `TEXT` | SHA-256 hex of the API key — identifies who called. Full key is never stored. |
| `model_id` | `TEXT` | Model that served the request, e.g. `qwen3-moe-235b`. |
| `tenant_id` | `TEXT` | Tenant from the API key record (empty if not set). |
| `timestamp` | `TEXT` | RFC3339Nano wall-clock time of the request. |
| `prompt_tokens` | `INTEGER` | Input token count. |
| `completion_tokens` | `INTEGER` | Output token count. |
| `endpoint` | `TEXT` | Protocol: `openai`, `anthropic`, or `embeddings`. |
| `client_ip_prefix` | `TEXT` | CIDR `/24` prefix of the client — e.g. `203.0.113.0/24`. Full IP is never stored. |
| `latency_ms` | `REAL` | End-to-end latency in milliseconds. |
| `finish_reason` | `TEXT` | `stop`, `length`, or `error`. |

**What is NOT stored:** prompt text, completion text, system prompts, user identifiers beyond the API key hash, full IP addresses.

---

## Storage schema

The `inference_audit_log` SQLite table is created (idempotently) by `Registry.Migrate`:

```sql
CREATE TABLE IF NOT EXISTS inference_audit_log (
    id                INTEGER  PRIMARY KEY AUTOINCREMENT,
    request_id        TEXT     NOT NULL UNIQUE,
    ...
);
CREATE INDEX IF NOT EXISTS idx_inference_audit_key_ts    ON inference_audit_log(api_key_hash, timestamp);
CREATE INDEX IF NOT EXISTS idx_inference_audit_model_ts  ON inference_audit_log(model_id, timestamp);
CREATE INDEX IF NOT EXISTS idx_inference_audit_tenant_ts ON inference_audit_log(tenant_id, timestamp);
```

The `UNIQUE` constraint on `request_id` makes recording idempotent: a gateway retry or at-least-once delivery will produce one row, never duplicates.

## Registry interface

The data layer is exposed through two methods on the `Registry` interface:

```go
// RecordInferenceEvent appends one event. Duplicate request_id is silently
// ignored (idempotent). A nil event is a no-op.
RecordInferenceEvent(ctx context.Context, event *InferenceEvent) error

// ListInferenceEvents returns paginated events matching the filter.
// All filter fields are optional. Default limit 100, max 1000.
ListInferenceEvents(ctx context.Context, req *ListInferenceEventsRequest) (*ListInferenceEventsResponse, error)
```

Filtering is supported by `api_key_hash`, `model_id`, `tenant_id`, time range (`After`/`Before`). Pagination uses an opaque cursor (`PageToken` / `NextPageToken`).

## Protobuf contract

The canonical wire shape is defined in `proto/purser/v1/inference_audit.proto`:

```protobuf
message InferenceEvent {
  string  request_id        = 1;
  string  api_key_hash      = 2;
  string  model_id          = 3;
  string  tenant_id         = 4;
  google.protobuf.Timestamp timestamp = 5;
  int64   prompt_tokens     = 6;
  int64   completion_tokens = 7;
  string  endpoint          = 8;
  string  client_ip_prefix  = 9;
  float   latency_ms        = 10;
  string  finish_reason     = 11;
}
```

Go bindings are generated into `go/gen/purser/v1/inference_audit.pb.go` via `make gen`.

## Privacy and compliance notes

| Requirement | How it is met |
|---|---|
| GDPR Art. 5 — data minimisation | Prompt and completion text are never written. Full IP is replaced with a `/24` CIDR prefix. |
| GDPR Art. 5 — purpose limitation | The table is append-only; records are not used for training or profiling. |
| AI Act Art. 12 — record-keeping | Every inference request is recorded with actor, model, timestamp, and token counts. |
| Deduplication / idempotency | `UNIQUE` on `request_id` prevents duplicate rows from gateway retries. |

> **Note:** Purser records the metadata of inference calls. Operators are responsible for any further data retention, deletion, and access-control obligations under their applicable law.
